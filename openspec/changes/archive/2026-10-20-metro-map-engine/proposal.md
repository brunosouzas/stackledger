# Proposal: metro-map-engine

## Why

The metro map is the reason stackledger exists: lines are journeys, stations are software, interchanges are the tools many journeys depend on ([ADR 3](../../../docs/adr/0003-lines-are-journeys.md)). The [map-engine spike](../../../docs/spikes/2026-10-20-map-engine/README.md) showed that existing engines reshuffle the map after small changes, so stackledger draws it with its own engine from stored station positions ([ADR 4](../../../docs/adr/0004-own-map-engine-with-stored-positions.md)). The spike's prototype is throwaway code; this change rebuilds it as a tested library and gives the owner a command to see the map before the website exists.

## What Changes

- A map library in two steps: `layoutMap` turns a view of the catalogue into geometry (station points, routed line paths, label boxes, zone areas, legend), and `renderSvg` turns the geometry into one self-contained SVG. The website (change `catalogue-site`) will reuse both.
- Routing: each hop between consecutive stops is routed on an octilinear grid and never passes through a station the line does not stop at; lines sharing a hop run in parallel in a fixed order.
- Stations: interchanges, line badges at terminals, labels placed to avoid collisions, a licence marker, a renewal ring in the `full` view only, and a muted style for deprecated components.
- Zones drawn as shaded areas, a legend, light and dark themes.
- Stations a line stops at but the layout does not place get a suggested position, drawn on the map and printed for the owner to copy into the `MapLayout`.
- A command `stackledger map <folder> [--view full|staff] [--theme light|dark] [--date YYYY-MM-DD]` that prints the SVG on stdout.

## Capabilities

### New Capabilities

- `metro-map`: what the map contains and how the engine lays it out (positions, routing, bundles, stations, labels, zones, legend, themes, markers, suggestions, determinism, safety of the SVG).
- `map-command`: the `stackledger map` command line.

### Modified Capabilities

- `mcp-server`: the global help scenario now lists `map` too. The catalogue needs no change: it already has `Line`, `MapLayout`, zones and the warnings for unplaced stops.

## Impact

- New code: `src/map/` (layout, routing, labels, render) and the `map` command in `src/cli.ts`.
- No new runtime dependency: the SVG is built as text.
- Documentation: README (Usage, the map image now produced by the tool), `docs/catalogue-format.md` (how positions and zones look on the map), a new `docs/map.md`.
- The spike folder stays as history.

## Out of scope

- Interactivity (zoom, filters, highlight on hover, click to item page): change `catalogue-site`.
- PNG or PDF output; the SVG is the only format.
- Writing suggested positions back to the catalogue; stackledger never writes into the catalogue.
- Automatic layout of the whole map; positions remain data.
- Live service status on the map (later in the roadmap).

## Implicit requirements

- **Errors and invalid input:** requirement. The map is drawn from the documents the views serve, so a catalogue with errors still produces a map from its valid parts; usage and folder errors exit 2. A hop the router cannot route is drawn as a straight segment and reported.
- **Limits:** requirement. The engine draws 200 stations and 20 lines within 5 seconds on CI hardware; each hop is routed inside the box of its two ends widened by three cells, and each search has a budget of 50,000 states, so a typo such as `[100000, 3]` ends in a reported straight segment instead of a long search.
- **Repetition and idempotency:** requirement. The same view, options and date produce byte-identical SVG. Adding a line or a station never moves a placed station.
- **Concurrency:** n/a. A pure function over in-memory data.
- **Security:** requirement. The SVG is meant to be embedded in a web page, so every catalogue text is escaped, the SVG has no scripts, no event attributes, no external references and no links, and the `staff` map shows nothing derived from hidden fields.
- **Logs and observability:** requirement. The command writes the SVG only to stdout; suggestions and problem counts go to stderr.
