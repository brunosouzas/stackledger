## Context

`renderSvg` (`src/map/svg.ts`) writes the layers in this order: background (a rect in `theme.background`), grid, zones, lines, stations, labels, then header and legend (the last two only with `chrome`; the site draws with `{ chrome: false }`, `src/site/data.ts`, so its viewBox is the frame's). Line and zone colours come from the catalogue; the theme colours come from `@brunosouzas/design-system` tokens through `src/map/themes.ts`. The background, grid and plain text are written by the local painter in `svg.ts`; `src/map/pieces.ts` serialises the design system's `Drawn` pieces. Everything goes through the strict writer in `src/map/xml.ts`, whose allow-list has no `fill-rule`, `transform` or `clip-path`. The spike of 2026-10-24 (`~/.hermes/spikes/stackledger/map-backgrounds/`, README and contact sheet) injected a backdrop group after the background rect of a 0.5.1 map and checked both themes at 1200 and 390 pixels.

## Decisions

1. **Data source, in two steps.** *Refresh* (rare, by hand, network): one Overpass API query over the bbox 51.455,-0.26 to 51.56,0.06 (Hammersmith to Greenwich), committed as `scripts/backdrops/london.overpassql`, then `osmtogeojson`, keep polygons, kind = water or park, transverse Mercator centred on 51.5/-0.1 in metres, drop water under 1.5 ha and parks under 8 ha, dissolve per kind; the result is committed as `scripts/backdrops/london-extract.json` (about 350 KB, ODbL, outside the package) with the Overpass timestamp as its extract date. *Generate* (offline, reproducible): `scripts/backdrops/build.mjs` reads only that extract, runs `mapshaper -simplify 2% keep-shapes`, drops slivers under 2 ha, orients the rings and writes `src/map/backdrops/london.ts`. Tool versions are pinned in the script (`npx --yes mapshaper@<x.y.z>`, `osmtogeojson@<x.y.z>`), never package dependencies. Measured in the spike: 4.5 MB raw, 350 KB filtered, 9.8 KB at 2% (716 vertices); 1% loses the river's shape, 5% is 20 KB.
2. **Generated TypeScript, not JSON.** `london.ts` exports the bounding box and the rings per kind, coordinates rounded to whole metres, with the ODbL header. A module keeps the data in `dist/` (already published) and needs no file read at draw time, so the read-only and offline scenarios hold.
3. **Cover, not fit.** `s = max(W / w, H / h)` over the SVG's viewBox and the data's bounding box, centred on the viewBox centre; the parts outside are cut by the viewBox itself. No `clip-path`, `transform` or `fill-rule`, which the writer does not allow: the points are computed in the engine, written with one decimal (deterministic), and the generator winds every hole opposite to its outer ring, so the default non-zero rule leaves holes empty. The site's map has no header and legend, so its viewBox, and the crop, differ from the CLI's; both are covered.
4. **Colours per surface, no opacity.** The spike showed that a lighter water and park tone on `light` and a deeper one on `dark` keep zones (already translucent), lines and labels readable. Opacity is not needed and would mix with the zone opacity. Tokens requested from the design system (AB#180), for `surface.light` and `surface.dark`: `backdrop.water`, `backdrop.waterEdge`, `backdrop.park`, `backdrop.credit`. The spike's provisional values are in the AB#180 card, not here.
5. **`neutral` stays flat.** The rings of the site's diagram panels were drawn too; they change every existing map. Kept out of scope, so the default is byte-identical.
6. **The grid stays.** It is a faint layer above the backdrop; removing it under a city is a separate visual decision.
7. **Credit in two places.** In the SVG (13 units, bottom-right) so a map copied alone keeps its attribution; on the site page as a readable line, because at 390 pixels the SVG text is about 3 pixels high.
8. **Setting location.** `spec.map.backdrop`, not `spec.site`, because `stackledger map` uses it too.

## Dependency

The code needs the design system release with the `backdrop` tokens (AB#180). Until then the change holds the spec only, in a draft pull request; the tests and code come in the same pull request after the bump.

## Test changes

New unit tests in `test/unit/` for the settings, the command, the engine layers and the data; new browser tests for the site. No existing snapshot changes: the example catalogue has no `spec.map`, so every committed map and README image stays the same. "Neutral is today's map" compares against fixed outputs from 0.5.1 (the committed `docs/images/map-*.svg`, plus the `staff` SVGs recorded into `test/fixtures/` before any code changes), not against a second render of the new code.
