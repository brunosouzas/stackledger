# stackledger: project context

Open-source software governance tool. It reads a software and licence catalogue (Backstage `catalog-info.yaml` format, kept in a separate Git repository or a local folder) and builds a static website with a metro-map view, a software list and licence reports. Owner: Bruno Souza. Human documentation lives in the brain vault under `10-personal/projects/stackledger/`.

## Technology

Stack: TypeScript, Node.js, Astro, zod, vitest, Playwright, GitHub Actions, OpenSpec

Implemented: the catalogue format and `stackledger validate` (`catalogue-model`), the SVG map engine and `stackledger map` (`metro-map-engine`), the read-only MCP server with the `full` and `staff` views (`mcp-server`), `stackledger build` with the static `full` and `staff` sites (`catalogue-site`), the licence report: `stackledger report`, the Reports page and `renewals.ics` of the `full` site (`licence-reports`), and Mac discovery: `stackledger discover`, `stackledger drift` with `--scaffold` and the `stackledger/<source>` annotations (`mac-discovery`), and `stackledger skills validate`, which reads and checks a set of agent skills, playbooks, agents and rules (`skills-source`, code in `src/skills/`), skipping what a `.stackledgerignore` file at the top of a given folder lists (`skills-ignore`, `src/skills/ignore.ts`), and `stackledger skills map`, which writes Markdown pages with Mermaid diagrams of the set's declared relations into a folder it owns, with `--check` for pipelines (`skills-mermaid`, `src/skills/graph.ts`, `mermaid.ts`, `map-command.ts`), and the Skills section of `stackledger build` with `--skills` and `spec.skills.folders`: the skills map file `stackledger-skills.yaml` (`src/skills/lines.ts`), the skills metro map with playbook zones (`src/skills/metro.ts`), the relation diagram (`src/map/relations.ts`), the page data (`src/site/skills-data.ts`, `skills-build.ts`) and the Astro pages under `site/src/pages/{skills,skill-map,rules,playbooks,agents}/` (`skills-site`), and station labels that wrap instead of being cut, with the rule count on skills stations (`station-labels-and-rules`, `src/map/labels.ts`, `layout.ts`), and the home page at `/` with the map at `/map/`, the default title `stackledger` and `spec.site.home` (`site-home`, `site/src/pages/index.astro`, `src/site/relative.ts` for the home links' exemption), and the city backdrop of the software map: `spec.map.backdrop` and `stackledger map --backdrop`, `neutral` or `london`, its OpenStreetMap credit in the SVG and under the site's map frame (`map-backgrounds`, `src/map/backdrops/` generated by `scripts/backdrops/`, `src/map/svg.ts`, colours from the design system's `backdrop` tokens in `src/map/themes.ts`). The publishable npm package, owner-approved release workflow, catalogue repository pipeline template and protected hosting recipes (`catalogue-deployment`) are implemented. Released on npm: 0.1.0 to 0.4.0 as `stackledger` (deprecated), 0.4.1 as `@brunosouzas/stackledger` (the same code under the npm organisation's scope; the command stays `stackledger`), 0.5.0, with the identity of `@brunosouzas/design-system` (`design-system-identity`, `home-banner`, `design-system-pieces`, `round-bends`), 0.5.1, with maps never shown larger than drawn (`map-scale`) and the design system 0.4.0, and 0.6.0, with the city backdrop of the software map (`map-backgrounds`) and the design system 0.5.3, once its publish job is approved; the fictitious demo is rebuilt by hand following `docs/demo.md`. The rest of the roadmap is not implemented: say so instead of describing files that do not exist.

Layout: `src/` the CLI and its modules (`src/map/` map engine and diagrams, `src/site/` site data, build, publication, `src/discovery/` the Mac sources, sandboxed runner and snapshot); `site/` the Astro project shipped in the package and copied into the build's staging folder; `test/unit`, `test/integration` (vitest) and `test/browser` (Playwright); `examples/northwind/` the fictitious example catalogue and `examples/northwind-machine/` its fictitious Mac snapshot, `examples/northwind-skills/` a fictitious skill set with a skills map file.

- Build: `npm run build`
- Test: `npm test` (vitest; build first for CLI integration tests)
- Timing test: `npm run test:perf` (alone, after the build)
- Browser test: `npm run test:browser` (Playwright with Chromium; `npx playwright install chromium` once)
- Run locally: `node dist/cli.js --help`

## Rules for this repository

- Integration branch: `main`.
- Releases only via `release.yml`: the merge of a pull request that changes `version` in `package.json` (or a version tag pushed by the owner), then the owner-approved environment (`npm`); see `docs/release.md`. Never publish from a local agent session.
- Board area: `setup` (Azure Boards, project `brunosouzas`).
- OpenSpec: yes, see `openspec/`. The order of the planned changes is in `docs/roadmap.md`.
- Project-wide decisions are ADRs in `docs/adr/` (index in `docs/adr/README.md`). Read them before a design; a change that contradicts one needs a new ADR that supersedes it, and the README's short explanation of that decision is updated in the same pull request.
- No real catalogue data in this repository, ever: examples, fixtures, tests and the demo use fictitious companies and people. Bruno's own catalogue lives in a private repository. Reason: a catalogue maps its owner's attack surface (versions, VPN, secret stores).
- The tool only reads the machine it inspects: no `sudo`, no writes outside its output folder, no network calls during discovery, no telemetry.
- Discovery tests never use real machine data: fake hosts, fake programs and temporary folders only (`test/virtual-host.ts`, `test/integration/discover-helpers.ts`). Never run `brew`, `npm`, `pipx` or `mas` plainly to look at something, never read or write the real `~/.stackledger`, and use `username` in every `/Users/` path (a docs test checks it). Tests that need the real sandbox or `plutil` run only on macOS (`describe.runIf(onMac)` from `test/discovery-helpers.ts`, that is `process.platform === 'darwin'`).
- A secret value never appears in the catalogue schema. A catalogue entry may name a password-manager item, never hold a credential.
- Public text (README, docs, specs, commit messages) is in English.
